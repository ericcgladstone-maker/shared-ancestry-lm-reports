# GPT Review of v7 (2026-10-30)

Exploratory build review. Question: in a controlled environment, can we predict the structures a message has passed through? This report checks five earlier technical amendments, the mistakes table against the rejected manuscript and Reviewer 1, requirements for building a working predictor, and the new compound-versus-relay comparison. No preregistration, freeze, or procedural-governance advice is included.

# EXECUTIVE ANSWER

YES. V7 applies all five substantive amendments requested in my v6 review. It is a coherent design for controlled production experiments, but it does not yet specify an unambiguous end-to-end structure-prediction system. Most consequential are the absence of a unified prediction task/interface, the lack of executable graph/package/prompt/feature definitions, and a factual-input mismatch in the new SD-same+3 versus R5 comparison. The new compound analysis is worth including once its source package and operation sequence are described accurately.

# I. FIVE V6 AMENDMENTS

1\. P3 increment from relational text features: YES. Part V defines P3 as the paired held-out ΔAUC \= A\_r − A\_0, comparing the text-only pairwise model with a text-only pooled-feature baseline on the same full-access neutral IND/DEP sets. H8 excludes world alignment and matcher-derived oracle features from both models. This tests the incremental predictive information in the specified cross-message features, not the failure of every possible single-message aggregation.

2\. H8 inherited-deviation support: YES. A\_s is the pooled baseline augmented with a validated world-anchored shared-deviation statistic. H8 requires a positive lower interval bound for A\_s − A\_0 and computes (A\_s − A\_0)/(A\_r − A\_0) only when the paired denominator is supported, reporting a point threshold of 0.5 and a paired interval. Because A\_s has authoritative world-record information unavailable to A\_r, this is corroborating mechanism evidence, not a causal decomposition of the text-only learner's information.

3\. Attribution-safe validation: YES. Principle 9 does not reject or retry an output because its Sources field is absent, invalid, or unparsable. These are recorded outcomes. Generative concealment therefore no longer contradicts the validator, and stripping is separately checked as a deterministic deletion.

4\. Natural and scripted matcher validation: YES. Part VI now includes 240 naturally generated texts coded without condition or model-feature labels, 60 independent double-codings, a minimum natural class count, adjudication, and separately evaluated scripted challenges with hard negatives. Each validation stream remains distinct. The implementer must still verify that each scripted edit genuinely produces its asserted semantic label.

5\. Conditional out-of-fold inference: YES. Part VIII adopts whole-world resampling of fixed out-of-fold predictions, a fixed-template-pool and fitted-model estimand, and centered bootstrap comparisons for P2 and P3. It no longer claims to estimate retraining or unseen-template uncertainty.

# II. MISTAKES TABLE AND REVIEWER 1

6\. Motif-specific prompts. Safeguard: shared function prompt pools and matched templates. Assessment: substantially sufficient against explicit condition-prompt leakage, but not a guarantee that “only structure can explain a prediction.” Node-function sequence, source information packages, synthesis input counts, length, and other procedure-specific changes can still be predictive. Some are legitimate components of the named treatments. The introduction should say that condition-specific prompt wording is neutralized, not that all other procedural differences vanish.

7\. Inert parallel branches. Safeguard: non-ancestral negative controls and observing several messages in Study 2\. Assessment: appropriate. The dispatcher must verify actual upstream ancestry and distinguish shared-key replay from the independently seeded full-run H1 comparison.

8\. Original compound not wired. Safeguard: parent-text lineage audit. Assessment: necessary but not sufficient. An audit that checks text against the parent list in the implemented graph will still pass a graph that declares the wrong parents. Add an independently specified expected graph fixture asserting that the synthesis output is a direct ancestor of every SD-same+3 and SI-same+3 terminal, with a six-call longest path \[observe, rewrite, synthesize, rewrite, rewrite, rewrite\]. Verify that actual synthesis output, not world facts, begins the downstream chain.

9\. Trace metadata encoded the label. Safeguard: no structure-bearing metadata in predictors. Assessment: sufficient for the text-only tasks if enforced as an input/feature-access whitelist. World-record alignment is legitimate in explicitly labeled privileged/anchored analyses but must never leak into the text-only models through metadata, dataset identifiers, or feature calculations.

10\. Four test worlds and trial-level intervals. Safeguard: sixty worlds, world-held-out evaluation, whole-world intervals. Assessment: addresses the main dependence problem. Generalization is to the specified authored worlds and fixed models, not automatically to human communication or unseen instruction distributions.

11\. Post hoc mechanism stories. Safeguard: H8 support condition and process measures reported as associations. Assessment: largely appropriate. Classification gain alone is not evidence of inherited omissions, and increases in depth or fan-in classification do not identify a unique mechanism without a corresponding comparison.

# OMISSIONS FROM THE MISTAKES TABLE

12\. Reader and classifier formerly differed in training and available inputs, so their gap could not identify residue-method alignment. V7's text-only comparisons, training-world examples, and descriptive framing partly repair this distinct Reviewer 1 concern. Add it to the table if the table is intended to be complete.

13\. The original semantic/formal/trace taxonomy and its 14 features were not cleanly aligned, and a length-only predictor was already strong. V7's overlapping operational families, length baseline, and ablations are the safeguard. Neither the table nor a revised article should imply that feature groups identify separate latent constructs.

14\. Calibration, motif probability outputs, candidate-source posterior, and fidelity confidence were not evaluated coherently for the same scientific target. V7 retains structure-prediction Brier/log-loss and explicitly drops the other tasks. This withdrawal and replacement should be named in the table rather than treating the original diagnostics as validated.

15\. Very uneven motif and message-length subgroup performance was narrated with uncertain denominators. V7's subgroup counts, world-level intervals, and bounded interactions address part of the concern. The table should identify this safeguard so striking small-cell accuracies do not acquire unsupported explanations again.

16\. The original 89-trial cross-family comparison was narrow. V7's second producer in Study 1 and selected Study 2 cells, two reader families, and specified transfer contrasts improve it, but its actual model IDs and transfer procedure must be implemented. The table omits this previously separate reviewer concern.

17\. Reviewer 1 challenged external validity and claims about human communication. V7 explicitly limits the claim to local language-model pipelines and treats an external corpus as optional. This scoping is another omitted safeguard. It does not require reinstating trace observability or clustered reinforcement.

These omissions do not defeat the two-study architecture. They do mean that the six-row mistakes table is a selective summary rather than a complete answer to the rejection review.

# III. WHAT A BUILDER STILL NEEDS

The following are implementation gaps, not requests for governance or additional experiments.

B1. Predictor task and output contract \[critical\]. Study 1 has seventeen generation conditions but mainly trains binary and small multiclass discriminators. An unknown incoming message does not announce that it is SI-same or SD-same, or R1/R3/R5. Specify whether the user-facing task outputs a vector of ancestry attributes (rewrite-depth class, synthesis occurrence, independent roots), a mutually exclusive class among generated histories, or a collection of named contrast scores. These are different estimands and interfaces. Study 2 should explicitly return a three-class IND/DEP/MIX probability and a same-root probability for each of the three pairs in a set, with no hidden generation-slot information. Define a task ID, permissible input fields, label ordering, output JSON and probability normalization, and a behavior for unsupported/ambiguous inputs. Otherwise successful contrast AUCs will not amount to a usable structure predictor. A unified multiclass or multi-property evaluation can be performed using the existing generated data without new topology calls.

B2. Machine-readable lineage and call keys \[critical\]. Each condition needs an exact DAG object with node IDs, node function, declared and realized parent IDs, input-package IDs, prompt family/template ID, canonical call role, seed, retry number, output hash, and terminal/set assembly rule. Specify canonical key serialization and stable hash-to-Ollama-seed mapping. Include world, replicate, block, producer/model digest, genre, access arm and attribution arm wherever those dimensions change the input. Intentional reuse across related structures must imply identical prompt bytes and parent hashes, not merely similarly named nodes. Keep the NC0/NCR1 condition-key exception only in the full-run distributional control. Define materialization/caching versus independent rerun of the same key and assert byte-identity where expected. Add independent reference fixtures for every topology, especially the compound.

B3. Worlds and package allocators \[critical\]. A runnable JSON schema must define world ID, event type, proposition ID and type, canonical fact value, core membership, source attribution, conflict-pair membership, logical incompatibility, numbers, and entity aliases. Provide explicit algorithms for F1/F2/F3 partitions and conflict co-location, SI-div overlap and union, equal-size Study 2 package pool generation and three-without-replacement draws, remainder handling when divisions are uneven, and template/package randomization. Test that the assigned union and planned co-location counts hold by construction. The new compound contrast needs its own package-equality assertion against R5.

B4. Literal prompt and model configuration \[critical\]. The document says that there are twelve templates per function across two families, but does not supply the actual source/rewrite/synthesis templates, neutral and concealment instructions, system messages, delimiters, input formatting, target lengths, or acceptable output grammar. Specify the chosen second producer, two readers, world-drafting model, embedding model, quantization/digests, context limits, max output tokens, Ollama version, seed option, temperature, top-p, batching, and concurrency. “Documented defaults” do not specify a stable sampling distribution across model revisions. At fixed packages, decoder diversity determines whether independently generated reports have distinctive errors to transmit.

B5. Feature registry and permitted information \[critical\]. Implement every original and new feature as a named deterministic transform with a declared input scope (text-only, set-of-texts, or oracle world-anchored), normalization, missing-data rule, and output shape. Define token/sentence segmentation, rare n-gram lengths and training-only rarity corpus, order similarity, embedding model and pooling, handling of entity/source markers, pairwise feature aggregation over an unordered triple, and invariance to display permutations. The P3 pairwise model should extend, not silently replace, the pooled baseline’s feature representation. Learn vocabulary, IDF weights, scalers, imputers, feature selectors, and any fitted encoder only from training worlds within each fold. Enforce an access whitelist so the text-only models cannot consume world IDs, path labels, source-record alignments, or key metadata.

B6. Proposition matcher and independent-reference null \[critical\]. Supply precise rules for matching clauses to propositions despite paraphrase, changed quantities, negation, entity substitution, multiple claims per sentence, omissions, partial preservation, qualifications, unsupported additions, and conflicting facts. State what counts as the same deviation in two messages, whether shared omission of an unmentioned but irrelevant proposition counts, and how to avoid double-counting one difference. Specify the full-access IND null estimator, its training-only conditioning and smoothing, and its normalization for differing numbers of propositions. An oracle-aligned feature must remain clearly separate from text-only prediction.

B7. Annotation and challenges \[high\]. The 240 natural messages and 60 double-coded examples require an explicit annotation unit (message × proposition and conflict pair), codebook, treatment of ambiguity, double-code selection, inter-rater statistic when classes are rare, and adjudication procedure. A colleague or RA uninvolved in the design can provide the independent labels. Scripted edits should be applied only where the base natural proposition state is verified. Verify both post-edit transitions and meaning-preserving hard negatives, rather than trusting a mechanical replacement to define ground truth. Forty edits from a few repeated bases do not provide forty independent semantic contexts. Report function/producer and natural/scripted error profiles separately.

B8. Dataset and split wiring \[high\]. Define immutable IDs for each world, block, call, text, set, pair, ancestry edge, generation slot and presentation position. Distinguish unique generated messages from repeated labeled records. Group all descendants and reused outputs into the same world fold. Specify class assignment for multiclass and pairwise models, set assembly and permutation, and how labels for the new compound contrasts enter prediction tasks. Store parent hashes and actual text bytes so that ancestry can be audited without relying on a motif name.

B9. Output validation and retries \[high\]. Supply the actual genre/function length targets, forbidden meta-commentary patterns, empty/timeout rules, retry-seed mapping, and treatment of a terminal failure. Avoid silent exclusion of short, content-poor or highly altered messages, since validity filtering may itself depend on ancestry. As v7 now correctly says, never retry solely because a Sources field is missing, malformed, or out-of-inventory. Record marker compliance as a separate output variable. Define resume and caching semantics so an interrupted multi-day run cannot mix model versions or regenerate different text under the same key.

B10. Training, readers and evaluation \[high\]. Fix classifier solver, penalty definition, scaling, class weights, tie handling, probability calibration, and multiclass aggregation. Give the reader’s exact label descriptions, training-example selection/order, JSON schema, and invalid-output representation separately for single-message and set tasks. Define which transfer evaluations train on one producer or genre and test directly on the other rather than retraining. Report world-held-out confusion matrices, event-type slices, paired model comparisons, and calibration. The L2 logistic learner is an interpretable benchmark, but it need not be the best predictor of semantic ancestry. Evaluate embedding and flexible text models on the same leak-free splits if predictive quality is the goal.

B11. Operational storage and audit \[medium\]. The call manifest needs stable serialization, output hashing, run IDs, model/config fingerprints, execution position, failure/retry history and elapsed time. Make the pipeline idempotent and resumable. Add unit tests for exact graph ancestry, source-package equality, key-input identity, no cross-fold shared ancestors, correct random presentation order, and no oracle-feature leakage. These are more valuable to predictive correctness than a ceremonial declaration that the design is finished.

# IV. WHAT MAY KEEP THE SYSTEM FROM PREDICTING WELL

P1. A collection of contrast-specific successes does not necessarily classify an unknown history. The original paper attempted a common motif-class recovery task, whereas Study 1’s principal evidence is pair-specific. Add a joint multiclass or interpretable multi-property readout using the generated condition labels, and expose ambiguity where graph histories are observationally equivalent. This recovers parity with the scientific question without reviving the original eight confounded motif labels.

P2. Independent observer realization may contain too little variation. SI-same/SD-same and full-access IND/DEP share world records and prompt templates, differing largely in seeded model draws and ancestry. If the primary producer writes nearly identical observations for the same world, synthesis and rewriting cannot reliably preserve distinctive independent errors. Measure observer diversity and conflict-resolution variation before and after rewriting. Explore whether weak performance is a property of the chosen model/decoding setting rather than of ancestry in all systems.

P3. Rewriting can erase structural evidence. Three later rewrites may remove rare phrasing, omissions, source cues and conflict choices after synthesis. Inspect stage-by-stage trace retention and not just terminal classification. A null compound result at six calls is not proof that compositions never leave a signature.

P4. Cross-message models may rely on near-duplicate overlap. Rare word sequences and embedding similarity can detect siblings of a shared source, but may fail under strong paraphrase or a changed producer. Evaluate text-only similarities against validated world-anchored shared deviations without conflating their information access. The second producer in full-access neutral Study 2 is useful for testing whether the signal is producer-specific.

P5. Uniform generated worlds can compress or artificially amplify the task. One schema, fourteen event types, authored records with exactly two conflict pairs, and one drafting model may impose lexical or information regularities that affect both positive and negative results. Inspect error distributions by event type, conflict plausibility, input length and source density. Report the source distribution to which the predictor is actually tuned.

P6. The selected classifier may be underpowered for subtle content relations. Logistic regression on engineered formal/relational features is a useful control, but entailment, semantic substitutions and cross-report inconsistencies may be better captured by learned textual representations. Compare with the planned flexible/embedding baselines under the same held-out worlds and information rules.

P7. Remaining production-procedure shortcuts can inflate apparent structure recovery. A classifier may detect the footprint of synthesis, the quantity of text presented upstream, or condition-specific coverage rather than an abstract graph signature. Diagnose generalization across matched prompt variants, producer and genre, and interpret each favorable contrast at the level actually manipulated.

# V. COMPOUND COMPARISON: SD-SAME+3 AND SI-SAME+3 VERSUS R5

The new comparison uses existing generated conditions and corrects the original paper's missing first-stage ancestry. It answers a restricted question: at the same longest-path length of six calls, can a terminal output reveal an upstream synthesis module rather than a simple rewrite chain? The Part IV table nevertheless omits the following differences and overstates a match.

C1. Source information is not guaranteed equivalent \[critical\]. The compound table says that both R5 and SD-same+3 use “the full world record.” Part V explicitly assigns the full world record to R5, but assigns all other Study 1 conditions, including SD-same, SI-same, and their downstream branches, packages under Part IV. SI-same and SD-same receive identical packages to each other, but “identical” does not imply “full world.” Without a literal assignment rule, compound recognition can reflect differing factual coverage. Smallest correction: in the compound comparison, explicitly give SI-same and SD-same the entire world record, matching R5, and audit those package IDs. Alternatively, generate an R5 reference that receives exactly the package assigned to SD-same/SI-same. The former uses existing conditions without extra producer runs but should be used consistently throughout the matched SI/SD arm.

C2. Six-call paths do not contain the same operations \[major\]. R5 has \[observe, rewrite, rewrite, rewrite, rewrite, rewrite\]. SD-same+3's longest path is \[observe, rewrite, synthesize, rewrite, rewrite, rewrite\]. The compound replaces one serial rewrite with a synthesis node that combines three incoming rewritten branches. The number and position of rewrites therefore differ even though longest-path length matches. This is an inherent part of a branch-and-synthesis \*total effect\*, not an eliminated nuisance factor. The table should identify it explicitly and not claim that only topology changed while node functions stayed fixed.

C3. Input cardinality and token exposure at the third step differ \[major\]. The compound synthesis sees three inputs containing potentially overlapping observations, whereas R5's corresponding third node rewrites one parent. Total input tokens, degree of redundancy, cumulative proposition coverage, and opportunities to reconcile or duplicate conflicting claims can differ. Measure them as intermediate process quantities and treat them as channels of the tested procedure, not as matches.

C4. Root count differs for the independent-source variant \[major\]. SD-same+3 and R5 both start from one observed root, but SD-same has three sibling rewrites of that root before synthesis. SI-same+3 has three \*independent observation roots\* feeding their own rewrites, versus R5's single root. The independent variant therefore changes both number of roots and synthesis. State that SI-same+3 versus R5 is a broader total effect than SD-same+3 versus R5.

C5. The total-call accounting is incomplete \[medium\]. SD-same+3 uses one observation, three sibling rewrites, one synthesis, and three downstream rewrites: eight producer calls versus R5's six. SI-same+3 uses three observations, three rewrites, one synthesis, and three downstream rewrites: ten versus six. The current table gives only eight versus six. Neither call-count difference is, by itself, a visible input under dispatcher isolation, but the extra upstream branches change what reaches synthesis.

C6. Rewrite-template matching needs an explicit slot map \[medium\]. R5 has five serial rewrite stages, while a compound longest path has four rewrites separated by a synthesis. State which R5 rewrite templates correspond to the first and last three compound rewrites and which R5 rewrite has no counterpart. Also state the auxiliary branch-template assignment. “Matched by block and slot” is not executable without defining whether slots mean longest-path positions, rewrite ordinal numbers, or call-role keys. Reusing a key for different parent text would violate the exact-input invariant.

C7. The compound target and classifier labels need to be connected \[medium\]. Part IV introduces the comparison, but the seventeen-condition table and H2/H5 model descriptions do not say whether SD-same+3 versus R5 and SI-same+3 versus R5 are trained as binary classifiers, included in a three-class confusion matrix, or only inspected descriptively. Define both binary readouts and, if useful, a three-class R5/SD-same+3/SI-same+3 readout from existing outputs. Do not describe its result as general recovery of all “compound motifs,” since one composition and its operational substitution are tested.

# VI. PRACTICAL PRIORITIES

First verify the graph oracle and make factual input packages literally equal in the compound comparison. Next define the actual output task for the predictor rather than relying exclusively on contrast-specific AUCs. Then supply exact prompts, package allocators, call-key namespaces, and feature transforms with machine-checkable non-leakage boundaries. Implement the matcher and its natural/scripted validation so inherited-deviation analyses measure genuine text variation rather than scripted artifacts. Evaluate prediction across held-out worlds, event types, prompts, producers, and genres, distinguishing loss of structural information from the limitations of a particular learner.

The broad research question is preserved, but the scientifically supported answer will concern which of these generated histories are recoverable under which controlled conditions. Some histories are observationally indistinguishable from one message. Reporting that limit is part of answering the question, rather than a failure of the prediction system.
